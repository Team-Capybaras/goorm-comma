# Park 도메인

공원(지역) 기본 정보를 관리하는 도메인입니다.

## 개요

`park` 도메인은 서울시 공공 API 데이터의 최상위 개념인 공원(지역) 정보를 관리합니다. 모든 다른 도메인의 테이블들이 `park` 테이블을 참조하여 지역별 데이터를 관리합니다.

## 엔티티

### 1. Park (공원 기본 정보)
**테이블**: `park`

공원(지역)의 기본 정보를 저장하는 최상위 테이블입니다.

**주요 필드:**
- `area_code` (PK): 지역 코드 (예: "POI110")
- `area_name`: 지역명 (예: "잠실한강공원")

**특징:**
- 모든 다른 도메인의 루트 테이블
- `area_code`를 통해 모든 관련 데이터 조회 가능
- 다른 도메인에서 FK로 참조됨

**관계:**
- 1:N: `ParkTag` (같은 도메인 내)
- 1:N: 다른 모든 도메인에서 참조 (`population`, `weather`, `parking`, `transit` 등)

---

### 2. ParkTag (공원 태그 연결)
**테이블**: `park_tag`

공원과 태그의 다대다 관계를 저장하는 연결 테이블입니다.

**주요 필드:**
- `park_tag_key` (PK): 공원 태그 키
- `tag_id` (FK): 태그 ID → `tag.tag_id`
- `area_code` (FK): 지역 코드 → `park.area_code`

**특징:**
- 공원과 태그의 다대다 관계 표현
- 하나의 공원에 여러 태그, 하나의 태그가 여러 공원에 적용 가능

**관계:**
- N:1: `Park` (FK: `area_code`)
- N:1: `Tag` (FK: `tag_id`, 다른 도메인)

---

## 도메인 역할

`park` 도메인은 다음과 같은 역할을 합니다:

1. **최상위 개념**: 모든 지역별 데이터의 루트 역할
2. **데이터 통합**: `area_code`를 통해 모든 관련 데이터를 통합 조회
3. **태그 관리**: 공원 분류를 위한 태그 연결 관리

## 사용 예시

```java
// 공원 정보 조회
Park park = parkRepository.findByAreaCode("POI110");

// 공원의 모든 태그 조회
List<ParkTag> parkTags = parkTagRepository.findByAreaCode("POI110");

// 공원 정보와 함께 다른 도메인 데이터 조회
// (예: 인구 현황, 날씨, 주차장 등)
```
